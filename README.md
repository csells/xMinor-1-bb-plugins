# BB Plugins

Плагины для [bb](https://getbb.app) — по одному на директорию в `plugins/`.
Каждый ставится отдельно, скачивать весь репозиторий не нужно.

| Плагин | Что делает | Статус |
| --- | --- | --- |
| [theme-toggle](plugins/theme-toggle) | Кнопка темы в футере сайдбара: клик — переключение день / ночь, наведение с задержкой, удержание или правый клик — меню выбора палитры и режима светлая / тёмная / как в системе. Иконка — квадрат, разрезанный по диагонали из правого верхнего угла в левый нижний: верх день, низ ночь, залитая половина показывает текущую тему; размер вровень с кольцами соседних плагинов | В каталоге bb, релиз `theme-toggle/v0.3.0`; обновление записи каталога на 0.3.0 (диапазон `^0.3.0`, новая иконка и описание) плюс имя автора — [PR #110](https://github.com/get-bb/marketplace/pull/110) |
| [server-status](plugins/server-status) | Состояние сервера в футере сайдбара: кольцо расхода оперативной памяти вокруг иконки (жёлтое с 80%, красное выше 90%), по клику — окно со сводкой: процессор, память, подкачка, диск, средняя нагрузка, время без перезагрузки, ОС и ядро | Релиз `server-status/v0.1.1`; заявка в каталог bb — [PR #89](https://github.com/get-bb/marketplace/pull/89) |
| [usage-meter](plugins/usage-meter) | Расход лимитов подписки Claude в футере сайдбара: два кольца вокруг иконки — внешнее пятичасовая сессия, внутреннее недельный лимит (жёлтое с 60%, красное выше 85%), лимит по модели с 60% зажигает точку в углу кнопки, по наведению или клику — попап со всеми окнами, временем сброса, планом и почтой аккаунта. Плюс страница «Usage»: та же сводка расхода, что у расширения Claude Code для VS Code (та же формула взвешенной стоимости, те же пороги и формулировки, сутки или неделя), а рядом то, чего в расширении нет, — прогоны workflow и фоновые раны /go, скиллы с весом инструкций, расход по проектам, моделям и тредам bb | Релиз `usage-meter/v0.2.4` (время сброса вместе с датой, когда окно уходит за полночь), тег выпущен; в каталоге bb — [PR #94](https://github.com/get-bb/marketplace/pull/94), диапазон `^0.2.0` покрывает 0.2.4, правка записи не нужна |
| [file-manager](plugins/file-manager) | Файловый менеджер машины, на которой работает bb: страницей в сайдбаре, вкладкой правой панели рядом с тредом и пунктом «File location» по правому клику на файловой ссылке в сообщении. Дерево с раскрытием папок на месте и галерея миниатюр, встроенный просмотрщик (картинки, PDF, видео, аудио, Markdown и подсветка кода — там, где у bb нет своей панели предпросмотра), быстрый просмотр по пробелу, свойства с размером папки по требованию, закладки папок, прыжок в рабочую папку треда, отправка файла агенту упоминанием (из меню и из «+» композера), адресная строка для вставки пути, возврат в последнюю открытую папку, загрузка перетаскиванием кусками с докачкой после обрыва (проверено на 5 ГБ), скачивание потоком, перемещение, копирование, переименование, удаление, распаковка архивов и просмотр их содержимого без распаковки — дерево папок с размерами и датами для zip, tar, tar.gz/bz2/xz, 7z и rar, русские имена из Windows-архивов читаются правильно; офисные документы (Word, Excel, PowerPoint, OpenDocument) уступает doc-review, который их показывает и комментирует; доступ ограничен домашней папкой пользователя, под которым работает bb | Релиз `file-manager/v0.8.0`; в каталоге bb ([PR #90](https://github.com/get-bb/marketplace/pull/90)), запись расширена до 0.7.x в [PR #122](https://github.com/get-bb/marketplace/pull/122), до 0.8.x — в [PR #196](https://github.com/get-bb/marketplace/pull/196). Версия 0.9.0 с просмотром архивов не выпущена, ставится из этого репозитория |
| [context-compact](plugins/context-compact) | Кружок контекста под композером становится кнопкой сжатия: клик по нему просит тред сжать контекст — тот же запрос, что делает `/compact`, — и результат приходит всплывашкой. Наведение не меняется: та же карточка с токенами и остатком. В сплите каждый композер сообщает свой тред, поэтому сжимается тот, чей кружок нажали | Не выпущен, ставится из ветки `@main` |
| [voice-ink](plugins/voice-ink) | Диктовка в композер локальной моделью Whisper на машине bb: без аккаунта, без API-ключа, звук наружу не уходит. Своя кнопка микрофона в композере режет речь по паузам и распознаёт её, пока человек ещё говорит, Escape отменяет запись; плюс плагин регистрирует голосовой AI-сервис bb, поэтому штатная кнопка микрофона тоже оживает (`BB_TRANSCRIPTION=voice-ink/local`). Модель выбирается в настройках: small — около 2.5 секунды ожидания после фразы, medium — около 7 секунд и заметно точнее (замер на 4 ядрах Xeon без GPU). Модель живёт в памяти между фразами и выгружается после 20 минут простоя. Микрофон в нижней панели сайдбара раскрывает последние диктовки, панель History хранит все — запись и полный текст с поиском: bb ждёт расшифровку 20 секунд, длинная диктовка в них не помещается, поэтому в композер уезжает начало с пометкой, а целиком текст дописывается в историю | Не выпущен, ставится из этого репозитория |
| [doc-review](plugins/doc-review) | Документы внутри bb — смотреть и комментировать в одной вкладке рядом с чатом. Открывает Markdown, PDF, Word, PowerPoint и Excel (и их старые и ODF-форматы): PDF — страницами, Word и PowerPoint — через LibreOffice на сервере с кэшем конвертаций, Excel — таблицей с форматированием, листами, объединениями и закреплёнными областями. Кнопка «Classic» включает штатный просмотрщик PDF браузера (поиск, зум, печать), есть скачивание оригинала. Комментарии как в Figma: выделение текста, рамка области на странице или слайде, ячейка или диапазон в Excel, весь документ; правый клик и ⌘⌥M. Черновики одной кнопкой уходят агенту в этот чат или в новый, к области прикладывается картинка фрагмента; агент закрывает каждый комментарий командой `bb doc-review resolve` или отвечает через `reply`, вкладка показывает это сразу. Страница «Doc Review» в сайдбаре — файлы с комментариями, недавние и обзор папок. В 0.2 сюда влит бывший pdf-viewer (Document Viewer) | Релиз `doc-review/v0.2.1`; заявка в каталог bb — [PR #368](https://github.com/get-bb/marketplace/pull/368), заменяет запись pdf-viewer, ждёт метку `v1-change` от мейнтейнера |
| [claude-design](plugins/claude-design) | Claude Design без отдельного браузера: проекты claude.ai/design привязываются к проектам bb и открываются во встроенном браузере bb рядом с чатом — из шапки треда, меню правой панели, палитры команд или страницы «Claude Design» в сайдбаре. Комментарии, отправленные в Claude Design кнопкой «Send to Claude», одной кнопкой уходят агенту: на странице проекта во встроенном браузере, из меню «+» композера или в новый чат; агент правит макет через MCP Claude Design и закрывает очередь (скилл `claude-design-comments`). Команда `bb claude-design` хранит привязки. Карточка «Use Claude Design without a VPN» даёт одну команду для Mac: SSH-туннель до сервера под launchd и PAC-правило, по которому через сервер идут только домены Claude — claude.ai видит болгарский адрес сервера, остальной трафик идёт напрямую. Сам плагин в Claude Design не ходит: claude.ai нельзя встроить фреймом, а работу делает агент | Не выпущен, ставится из этого репозитория |

## Установка

```sh
bb plugin install git:https://github.com/xMinor-1/bb-plugins.git@^0.2.0 --plugin theme-toggle --tag-prefix theme-toggle/
bb plugin install git:https://github.com/xMinor-1/bb-plugins.git@^0.8.0 --plugin file-manager --tag-prefix file-manager/
bb plugin install git:https://github.com/xMinor-1/bb-plugins.git@^0.1.0 --plugin server-status --tag-prefix server-status/
bb plugin install git:https://github.com/xMinor-1/bb-plugins.git@^0.2.0 --plugin usage-meter --tag-prefix usage-meter/
```

Каждая форма ставит последний релиз по тегу `<плагин>/vX.Y.Z` и видит
обновления через `bb plugin outdated`. Форма `@main` вместо диапазона берёт
текущее состояние ветки — так ставится то, что ещё не выпущено релизом.

`--plugin <имя>` берёт запись из `.bb/plugins.json`. Равнозначная форма — через путь:
`--subdirectory plugins/theme-toggle`.

Локально, из клона репозитория:

```sh
bb plugin install path:. --plugin theme-toggle
```

## Релизы

Каждый плагин версионируется отдельно тегом `<плагин>/vX.Y.Z`:

```sh
git tag -a theme-toggle/v0.3.0 -m "Release theme-toggle v0.3.0"
git push origin theme-toggle/v0.3.0
```

Версия в теге должна совпадать с `version` в `package.json` плагина. Тег не
переносят и не переписывают — на каждый релиз новый. Пока диапазон в записи
каталога (`^0.2.0`) покрывает новую версию, обновлять запись в каталоге не
нужно: bb сам увидит релиз. Для версий `0.x` смена второй цифры выходит за
диапазон — тогда запись в каталоге правится отдельным PR. Смена источника, названия, иконки или описания —
новый PR в каталог.

## Новый плагин

```sh
scripts/new-plugin.sh <имя> [--app]
```

Создаёт `plugins/<имя>` и регистрирует его в `.bb/plugins.json`. Остальные шаги —
в [CLAUDE.md](CLAUDE.md).

## Разработка

```sh
cd plugins/theme-toggle
npm install
npx tsc --noEmit        # проверка типов
bb plugin build .       # сборка dist/ (server.js, app.js, app.css + meta)
bb plugin dev .         # пересборка и перезагрузка на каждое сохранение
```

Требования: bb >= 0.39, `@get-bb/plugin-sdk` >= 0.4.8, Node 24.

`dist/` и `node_modules/` не версионируются — bb собирает плагин при установке
из git сам.
